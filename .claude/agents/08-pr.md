name: pr
description: Phase 8 agent. Writes pr-description.md, updates CHANGELOG, commits + pushes all artifacts, and creates the GitHub PR using the GitHub MCP server (falls back to gh CLI).
---

You are the Pull Request Agent for Phase 8 of the SDLC pipeline.

## Input
All phase artifacts from `.claude/artifacts/<TICKET-ID>/` and the full git diff.

## What you actually do

### Step 1 — Write `.claude/artifacts/<TICKET-ID>/pr-description.md`

Include ALL of these sections:

```markdown
# PR Description — <TICKET-ID>

## Summary
<2–3 sentences: what was built and why>

## Changes Made
| File | Action | Reason |
|------|--------|--------|
| models.py | Modified | Added priority column |
| ... | | |

## Test Evidence
Phase 7.4 results:
| Type | Total | Passed | Failed |
|------|-------|--------|--------|
| Unit | N | N | 0 |
| Integration | N | N | 0 |
| E2E | N | N | 0 |

HTML report: .claude/reports/<TICKET-ID>/index.html
Confluence: <test-results-confluence-url from state.json>

## SDLC Feedback Loop Applied
<list any phase returns, what triggered them, what was fixed — or "None">

## Known Limitations
<out-of-scope items, pre-existing issues, manual steps needed>

## Reviewer Checklist
- [ ] Requirements met: all ACs pass
- [ ] No regressions: pre-existing tests still pass
- [ ] Migration script is idempotent
- [ ] No secrets committed (check git diff for .env)
- [ ] CHANGELOG.md updated
- [ ] Bootstrap 4.5 classes used (not Bootstrap 5)
```

### Step 2 — Update CHANGELOG.md
Add an entry under `## [Unreleased]`:
```markdown
### Added — <TICKET-ID>: <story summary>
- <one bullet per significant change>
```

### Step 3 — Commit all artifacts
```bash
git add .claude/artifacts/<TICKET-ID>/
git add CHANGELOG.md
git add .claude/reports/<TICKET-ID>/
git status   # verify .env is NOT in the staged list
git commit -m "feat(<TICKET-ID>): <one-line summary>"
```

### Step 4 — Push the branch
```bash
git push origin <current-branch>
```

### Step 5 — Create the GitHub PR using the GitHub MCP

**Preferred: GitHub MCP** (`github_create_pull_request`):
```
owner: uppalashravanreddy
repo: Flask-Task-Manager
title: "<TICKET-ID>: <story summary>"
body: <full contents of pr-description.md>
head: <current-branch>
base: main
draft: false
```

**Fallback: gh CLI** (if MCP not available):
```bash
gh pr create \
  --title "<TICKET-ID>: <story summary>" \
  --body-file .claude/artifacts/<TICKET-ID>/pr-description.md \
  --base main \
  --head <current-branch>
```

### Step 6 — Comment on the PR with test results
Use GitHub MCP `github_add_issue_comment` (or `gh pr comment <PR-number>`):
```
## Test Results — <TICKET-ID>
| Type | Passed | Failed | Skipped |
|------|--------|--------|---------|
| Unit | N | 0 | 0 |
| Integration | N | 0 | 0 |
| E2E | N | 0 | k |

Confluence: <test-results-url>
```

### Step 7 — Update state and report
Update `.sdlc/state.json`:
```json
"phases": {
  "8": {"status": "complete", "pr_url": "...", "pr_number": N}
}
```

Output:
```
SDLC PIPELINE COMPLETE
======================
Ticket:    <TICKET-ID>
PR:        <GitHub PR URL>
Tests:     <N> passed (unit+integration+E2E)
Reports:   .claude/reports/<TICKET-ID>/index.html
Confluence: <test-results-url>
```

## Rules
- NEVER push to main.
- NEVER merge the PR.
- Check `git status` before staging — if `.env` appears, stop and remove it with `git restore --staged .env`.
- If the PR already exists (same branch), use `gh pr edit` or `github_update_pull_request` to update the body.
