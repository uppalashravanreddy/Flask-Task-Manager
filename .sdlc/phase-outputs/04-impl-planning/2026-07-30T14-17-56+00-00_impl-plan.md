## 2. Completed Tasks

### TASK-01: SECRET_KEY Hardcoding Fix

| Field | Detail |
|---|---|
| File | app.py |
| Description | SECRET_KEY was hardcoded as a string literal in the Flask application entry point, creating a security vulnerability by exposing the secret in source control. The value has been replaced with `os.environ.get('SECRET_KEY')` so the key is injected at runtime from the environment and never committed to the repository. |
| Definition of Done | app.py reads SECRET_KEY from os.environ; no hardcoded secret present in source; application starts correctly when SECRET_KEY is set in environment. [DONE — verified] |

### TASK-02: Version Pins in requirements.txt

| Field | Detail |
|---|---|
| File | requirements.txt |
| Description | requirements.txt previously contained extraneous entries (`datetime`, `wtforms.validators`) that are either part of the Python standard library or sub-modules rather than installable packages, causing pip install failures. These entries have been removed. Remaining dependencies now carry minimum version constraints (`flask>=3.0.0`, `flask-sqlalchemy>=3.0.0`, `flask-wtf>=1.2.0`, `wtforms>=3.1.0`) to ensure reproducible installs across environments. |
| Definition of Done | `pip install -r requirements.txt` completes without errors; all four valid packages install at or above the pinned floor version; spurious entries absent. [DONE — verified] |

### TASK-03: Test Suite conftest.py sys.path Fix

| Field | Detail |
|---|---|
| File | tests/conftest.py |
| Description | Test discovery failed because the `src/` package was not on `sys.path` when pytest collected tests from the `tests/` directory. A `conftest.py` at the repository root now inserts the project root into `sys.path` so that `from src.doc_sync import ...` imports resolve correctly in all test tiers (unit, integration, e2e). |
| Definition of Done | All 10 unit and integration tests are collected and pass without `ModuleNotFoundError`; no manual `PYTHONPATH` export required before running `pytest`. [DONE — verified] |

### TASK-04: src/__init__.py Package Marker

| Field | Detail |
|---|---|
| File | src/__init__.py |
| Description | The `src/` directory lacked an `__init__.py`, preventing Python from treating it as a package and causing import errors when tests attempted `from src.doc_sync import ...`. An empty `__init__.py` has been added to declare `src` as a regular Python package. |
| Definition of Done | `src/__init__.py` exists; `python -c "from src.doc_sync import collect_repository_facts"` executes without error; all test imports resolve. [DONE — verified] |

### TASK-05: Repository Scanner Implementation

| Field | Detail |
|---|---|
| File | src/doc_sync/repo_scanner.py |
| Description | Implements the `scan_repository(repo_path)` function that reads the six canonical repository files (`app.py`, `models.py`, `routes.py`, `forms.py`, `requirements.txt`, `src/main.py`) from a given root path. Returns a dictionary mapping each filename to its raw text content. Files that are absent or unreadable are mapped to an empty string rather than raising, satisfying AC-2 and enabling graceful handling of partial repositories. |
| Definition of Done | `scan_repository` returns a dict with all six keys; missing files yield empty string values; three unit tests in `tests/unit/test_repo_scanner.py` all pass. [DONE — verified] |

### TASK-06: Structured Fact Extractor Implementation

| Field | Detail |
|---|---|
| File | src/doc_sync/extractor.py |
| Description | Implements `extract_facts(file_contents)` which accepts the dict produced by the scanner and parses each file's text to derive structured metadata: framework and version, database model fields, route definitions, form classes, and declared dependencies. Any field that cannot be determined from the source text is set to the sentinel string `"Not Specified"` rather than `None` or omitted entirely, satisfying AC-3 and ensuring downstream formatting always has a printable value. |
| Definition of Done | `extract_facts` returns a populated facts dict; absent information surfaces as `"Not Specified"`; two unit tests in `tests/unit/test_extractor.py` all pass. [DONE — verified] |

### TASK-07: Markdown Page Creator Implementation

| Field | Detail |
|---|---|
| File | src/doc_sync/page_creator.py |
| Description | Implements `create_page(facts, version)` which formats the structured facts dict into a Markdown technical profile document. The document includes a header block, a versioned page title (satisfying AC-6), sections for each fact category (framework, models, routes, forms, dependencies), and a generation timestamp. |
| Definition of Done | `create_page` returns a non-empty Markdown string containing the version token; four unit tests in `tests/unit/test_doc_sync.py` all pass. [DONE — verified] |

### TASK-08: CLI Entry Point and Pipeline Orchestration

| Field | Detail |
|---|---|
| File | src/main.py |
| Description | Implements the `run_pipeline(repo_path, output_path)` function and the `if __name__ == "__main__"` block that wires together the scanner, extractor, and page creator. The CLI accepts `--repo` (path to repository root, defaults to `.`) and `--output` (destination file path for the generated Markdown). A version token derived from the current UTC timestamp is passed to `create_page` so each run produces a uniquely titled document. |
| Definition of Done | `python src/main.py --repo . --output out.md` executes without error and writes a Markdown file; the integration test in `tests/integration/test_pipeline.py` passes. [DONE — verified] |
